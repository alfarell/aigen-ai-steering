# Architecture decisions

Create an ADR when a change makes a durable decision about:

- ownership or data flow across the three repositories;
- database/schema ownership, migration, or cross-schema writes;
- HTTP/Kafka/token contracts;
- authentication/authorization;
- transaction, idempotency, concurrency, or retry strategy;
- package manager, test framework, or major dependency;
- rollout order or feature-flag behavior.

Use `ADR-template.md`, assign the next sequential identifier such as `ADR-0001`, and keep superseded records instead of deleting history.
